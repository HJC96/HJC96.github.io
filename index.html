About Me

안녕하세요. Java와 Spring Boot를 기반으로 백엔드 서비스를 개발하고 있는 한지찬입니다.

임베디드 소프트웨어 개발을 시작으로 차량 보안 시스템, 인증서 발급 시스템, 보안키 관리 시스템 등의 백엔드 개발을 경험했습니다.

단순히 기능을 구현하는 것을 넘어, 테스트하기 좋은 코드를 작성하고 데이터의 정합성을 유지하며, 변경에 유연한 시스템을 설계하는 데 관심이 있습니다.

최근에는 객체지향 설계, 헥사고날 아키텍처, 분산 시스템과 시스템 설계를 공부하며 실무에서 배운 내용을 정리하고 있습니다.

Engineering Notes

백엔드 개발 과정에서 중요하게 생각하는 기술적 문제와 설계 경험을 소개합니다.

1. 동시성 제어와 데이터 정합성

여러 사용자가 동일한 데이터를 수정하는 환경에서는 먼저 저장한 내용이 나중에 들어온 요청에 의해 사라지는 Lost Update 문제가 발생할 수 있습니다.

실제로 여러 담당자가 하나의 문서를 수정하는 기능을 개발하면서 비관적 락, 네임드 락, 낙관적 락을 검토했습니다.

사람이 브라우저에서 문서를 수정하는 경우 조회부터 저장까지의 시간을 하나의 DB 트랜잭션으로 관리하기는 어렵습니다.

이를 해결하기 위해 문서를 조회할 때의 버전을 클라이언트에 전달하고, 저장 요청에서 해당 버전을 검증하는 낙관적 오프라인 락을 선택했습니다.

기존 문서의 수정 충돌뿐 아니라 최초 저장 시 발생할 수 있는 중복 삽입 문제도 함께 검토했습니다.

2. 테스트하기 좋은 백엔드 설계

테스트 코드를 도입하면서 가장 중요하게 생각하게 된 것은 테스트 라이브러리의 사용법보다 프로덕션 코드의 설계였습니다.

외부 시스템이나 데이터베이스에 강하게 결합된 코드는 독립적으로 검증하기 어렵습니다.

이를 개선하기 위해 외부 의존성을 분리하고, Mockito와 WireMock을 활용해 외부 시스템의 응답과 장애 상황을 테스트하는 방법을 학습하고 적용했습니다.

또한 Testcontainers를 활용해 실제 MySQL 환경을 사용하는 통합 테스트를 구성하고, 테스트 간 데이터와 애플리케이션 컨텍스트를 격리하는 방법을 고민했습니다.

Spring Boot 테스트 격리 방법 읽기 →

3. 분산 시스템과 트랜잭션

여러 서비스가 하나의 비즈니스 기능을 처리하는 분산 시스템에서는 단일 데이터베이스 트랜잭션만으로 모든 작업의 일관성을 보장하기 어렵습니다.

예를 들어 주문 과정에서 재고 감소, 결제 요청, 주문 저장이 서로 다른 서비스에서 수행된다면 일부 작업만 성공했을 때의 처리 방법을 고민해야 합니다.

이러한 문제를 공부하면서 분산 트랜잭션과 보상 트랜잭션, 중복 요청을 안전하게 처리하기 위한 멱등성의 필요성을 살펴봤습니다.

특히 재시도가 가능한 시스템에서는 동일한 요청이 여러 번 도착하더라도 의도하지 않은 중복 처리가 발생하지 않도록 설계하는 것이 중요합니다.

4. 변경에 유연한 소프트웨어 아키텍처

테스트하기 좋은 코드를 고민하면서 객체지향 설계와 헥사고날 아키텍처에 관심을 갖게 되었습니다.

비즈니스 로직을 외부 시스템과 분리하고 의존성의 방향을 관리하면 외부 기술이 변경되더라도 핵심 도메인 로직에 미치는 영향을 줄일 수 있습니다.

최근에는 포트와 어댑터를 이용한 컴포넌트 간 의존성 분리, ArchUnit을 활용한 아키텍처 규칙 검증, 도메인 모델과 영속성 모델의 책임 분리 등을 공부하고 있습니다.
